Sanctions Territory Reference

Comprehensively sanctioned territories mapped to the ISO 3166 identifiers geolocation systems actually return · version 1.0.0 · built 2026-11-05

Institutions operating geolocation-based access controls must keep their blocked-territory configuration aligned with the comprehensive sanctions perimeter. That reconciliation is currently performed by hand, independently, at every institution, against prose legal sources of varying currency. This reference states the perimeter in the identifiers those systems use, cites a primary source for every record, and records every change.

Under-blocking is the failure everyone knows. A territory is designated, a configuration lags, prohibited transactions get through, and an enforcement action eventually follows.
Over-blocking is the failure nobody sees. When a programme is terminated, an institution that does not update its configuration continues to deny service to a jurisdiction the United States no longer comprehensively sanctions. No alert fires, because no control is designed to detect a transaction that was wrongly stopped. No metric records it, because nobody files a complaint saying they were improperly excluded. This checker reports both directions.

Where legal scope and technical identifier diverge

These are stated here rather than in a footnote, because an implementer who does not know about them will produce a configuration that looks correct and is not.

Crimea region of Ukraine (UA-43)The designation follows the Crimea region; geolocation products variously return ISO 3166-2 subdivision UA-43, country-level UA, or inconsistent labels. Implementers must document which signal they treat as authoritative.
Certain regions of Ukraine (Donetsk and Luhansk oblasts, non-government controlled areas) (UA-14 UA-09)The legal perimeter follows non-government controlled areas of Donetsk and Luhansk oblasts, while ISO 3166-2 codes UA-14 and UA-09 describe entire oblasts. Blocking at oblast granularity over-blocks relative to the designation; blocking at country UA under-blocks relative to oblast-level signals. No configuration is strictly correct — only a documented choice.

Using the feed

The machine-readable feed is generated from the same source file as this page and published at a stable address:

https://divine16.github.io/sanctions-territory-reference/feed.json

It is intended to be automated against. Records carry the same fields shown above, including the primary-source citation and the date each record was last verified against it.

Currency. A reference whose entire value is its currency must police its own. A scheduled process checks the age of the most recent verification on every record and raises an issue when it exceeds threshold, so staleness is visible rather than silent. Each record below carries its own last_verified date in the feed.

Limits. This reference covers comprehensive territorial programmes only. It is not a list of designated persons, it does not cover sectoral or list-based measures, and it is not legal advice. Verify against the cited primary source before relying on any record.
